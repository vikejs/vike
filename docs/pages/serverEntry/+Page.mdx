Define `+serverEntry.js` to control how your server starts in production: Vike builds it into `dist/server/index.mjs`, the file you run in production.

```ts
// +serverEntry.ts

// Your +server.js exports, e.g. { fetch }
import server from 'vike:server'

// Pseudo code
startServer({
  port: 3000,
  onRequest: (request) => server.fetch(request)
})
```

```bash
# Build: +serverEntry.ts => dist/server/index.mjs
$ vike build
# Run +serverEntry.ts
$ node dist/server/index.mjs
```

It gives you full control over your production server, for example to:
- Deploy to a platform without built-in support, e.g. AWS Lambda (see example below).
- Use another server framework, or a runtime API such as `Bun.serve()` and `Deno.serve()`.
- Use all CPU cores with Node.js's [`cluster`](https://nodejs.org/api/cluster.html) module.

> Without `+serverEntry.js`, `dist/server/index.mjs` is Vike's built-in server entry: a [srvx](https://srvx.h3.dev) server with first-class support for Node.js, Deno, and Bun (and potentially future runtimes). See <Link href="/server" />.

> Vike uses <Link href="/blog/universal-deploy">Universal Deploy</Link> under the hood: it provides Vike's built-in server entry and integrates Vike with deployment providers (e.g. Cloudflare and Vercel).


## `vike:server`

`import server from 'vike:server'` is your <Link href="/server">`+server.js`</Link> exports, e.g. `{ fetch }`. (If you don't define `+server.js`, then it's Vike's built-in server.)

You can use it to handle requests before they reach `+server.js`:

```ts
// +serverEntry.ts

import { serve } from 'srvx'
import server from 'vike:server'

serve({
  port: 3000,
  fetch(request) {
    if (new URL(request.url).pathname === '/health') return new Response('OK')
    return server.fetch(request)
  }
})
```


## Example: AWS Lambda

AWS Lambda calls the `handler()` function exported by `dist/server/index.mjs`. You can implement it natively or with srvx.

> With AWS Lambda, you usually serve the static assets `dist/client/` with a CDN, such as Amazon CloudFront.

### Native

```ts
// +serverEntry.ts

import type { APIGatewayProxyHandlerV2 } from 'aws-lambda'
import server from 'vike:server'

// AWS Lambda calls handler() for each request (Lambda function URL or API Gateway HTTP API)
export const handler: APIGatewayProxyHandlerV2 = async (event) => {
  // AWS Lambda event => Request
  const url = new URL(`https://${event.requestContext.domainName}${event.rawPath}`)
  url.search = event.rawQueryString
  const headers = new Headers(event.headers as Record<string, string>)
  if (event.cookies) headers.set('cookie', event.cookies.join('; '))
  const body = event.body ? Buffer.from(event.body, event.isBase64Encoded ? 'base64' : 'utf8') : undefined
  const request = new Request(url, { method: event.requestContext.http.method, headers, body })

  // Your +server.js exports
  const response = await server.fetch(request)

  // Response => AWS Lambda result
  return {
    statusCode: response.status,
    headers: Object.fromEntries([...response.headers].filter(([name]) => name !== 'set-cookie')),
    cookies: response.headers.getSetCookie(),
    body: Buffer.from(await response.arrayBuffer()).toString('base64'),
    isBase64Encoded: true
  }
}
```

### srvx

```ts
// +serverEntry.ts

import { toLambdaHandler } from 'srvx/aws-lambda'
import server from 'vike:server'

// AWS Lambda calls handler() for each request
export const handler = toLambdaHandler({ fetch: server.fetch })
```


## Example: srvx

> Vike's built-in server entry already uses srvx: this example is only meant as a starting point for customizing it.

```ts
// +serverEntry.ts

import { fileURLToPath } from 'node:url'
import { serve } from 'srvx'
import { staticMiddleware } from 'srvx/static'
import server from 'vike:server'

serve({
  port: 3000,
  // Serve the static assets (dist/client/)
  middleware: [staticMiddleware({ dir: fileURLToPath(new URL('../client', import.meta.url)) })],
  // Your +server.js exports
  fetch: server.fetch
})
```


## Development

If you define <Link href="/server">`+server.js`</Link>, then `+serverEntry.js` is only used in production: in development, `$ vike dev` uses Vite's development server with your `+server.js` (as usual, with HMR).

If you don't define `+server.js`, then `$ vike dev` runs `+serverEntry.js` also in development. It's a convenient way to manually integrate Vike into your server with <Link href="/renderPage">`renderPage()`</Link>:

```ts
// +serverEntry.ts

import express from 'express'
import { fileURLToPath } from 'node:url'
import { createDevMiddleware, renderPage } from 'vike/server'

const app = express()

if (import.meta.env.DEV) {
  // Vite's development middleware (HMR, transpiling, static assets, ...)
  const { devMiddleware } = await createDevMiddleware()
  app.use(devMiddleware)
} else {
  // Serve the static assets (dist/client/)
  app.use(express.static(fileURLToPath(new URL('../client', import.meta.url))))
}

app.get('/{*vikeCatchAll}', async (req, res) => {
  const pageContext = await renderPage({ urlOriginal: req.originalUrl, headersOriginal: req.headers })
  const { httpResponse } = pageContext
  httpResponse.headers.forEach(([name, value]) => res.setHeader(name, value))
  res.status(httpResponse.statusCode)
  httpResponse.pipe(res)
})

app.listen(3000)
```

- `$ vike dev` runs `+serverEntry.js` with Vite: TypeScript, path aliases, Vite plugins, and `import.meta.env.DEV` work (no need for `tsx`/`ts-node`).
- When you modify `+serverEntry.js` (or a file it imports), `$ vike dev` restarts your server. Modifying a page doesn't restart your server: the page is updated with <Link href="/glossary#hmr">HMR</Link> as usual.
- <Link href="/createDevMiddleware">`createDevMiddleware()`</Link> returns the Vite development server that `$ vike dev` created.
- Only `$ vike dev` runs `+serverEntry.js`: `$ vite dev` shows an error (Vite's CLI always starts Vite's own server).

### Example: `Bun.serve()`

```ts
// +serverEntry.ts

import { createDevMiddleware, renderPage } from 'vike/server'
import { fetchNodeHandler } from 'srvx/node'

const devMiddleware = import.meta.env.DEV ? (await createDevMiddleware()).devMiddleware : null

Bun.serve({
  port: 3000,
  async fetch(request) {
    if (devMiddleware) {
      // Vite's development middleware, through srvx's emulation of Node.js's req/res
      let handled = true
      const response = await fetchNodeHandler(
        (req, res, next) =>
          devMiddleware(req, res, () => {
            handled = false
            next()
          }),
        request
      )
      if (handled) return response
    } else {
      // Serve the static assets (dist/client/)
      const file = Bun.file(new URL(`../client${new URL(request.url).pathname}`, import.meta.url))
      if (await file.exists()) return new Response(file)
    }
    const { httpResponse } = await renderPage({ urlOriginal: request.url, headersOriginal: request.headers })
    return new Response(httpResponse.getReadableWebStream(), {
      status: httpResponse.statusCode,
      headers: httpResponse.headers
    })
  }
})
```

```bash
# Development (with package.json#scripts.dev set to "vike dev")
$ bun --bun run dev
# Production
$ vike build
$ bun dist/server/index.mjs
```

> `Deno.serve()` should work the same way.

> Vite's development middleware is a [Connect](https://github.com/senchalabs/connect) middleware (it uses Node.js's `req`/`res`), which is why it needs a bridge such as srvx's `fetchNodeHandler()`. Vite wants to move away from Connect, see [vitejs/ecosystem#16](https://github.com/vitejs/ecosystem/issues/16).


## Static assets

`+serverEntry.js` is responsible for serving the static assets `dist/client/`. (Because `+serverEntry.js` replaces Vike's built-in server entry that serves static assets.) See the srvx example above.

> See <Link href="/precompress" noBreadcrumb /> to generate `.br`/`.gz` files for your static assets at build time.


## Pre-rendering

<Link href="/pre-rendering">Pre-rendering</Link> doesn't execute `+serverEntry.js`.

> If all your pages are pre-rendered, `dist/server/` is still kept (Vike otherwise removes it, see <Link href="/prerender">`+prerender` > `keepDistServer`</Link>).
