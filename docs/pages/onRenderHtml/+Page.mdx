The `onRenderHtml()` hook defines how pages are rendered to HTML.

The hooks `onRenderHtml()` and <Link href="/onRenderClient">`onRenderClient()`</Link> are essentially the glue code between Vike and your UI framework (React/Vue/Solid/...).

> If you use a <UiFrameworkExtension />, then you don't need to (and shouldn't) define `onRenderHtml()` as it's already defined by <UiFrameworkExtension name noLink />.

```ts
// +onRenderHtml.ts
// Environment: server

export { onRenderHtml }

import type { PageContextServer } from 'vike/types'
import { escapeInject, dangerouslySkipEscape } from 'vike/server'
import { renderToHtml, createElement } from 'some-ui-framework'

async function onRenderHtml(pageContext: PageContextServer){
  const { Page, data } = pageContext
  const pageHtml = await renderToHtml(createElement(Page, data))

  const documentHtml = escapeInject`<!DOCTYPE html>
    <html>
      <head>
        <title>My SSR App</title>
      </head>
      <body>
        <div id="page-root">${dangerouslySkipEscape(pageHtml)}</div>
      </body>
    </html>`

  return {
    documentHtml,
    pageContext: {
      // We can define pageContext values here
    }
  }
}
```

Where `pageContext.Page` is the <Link href="/Page">`+Page` value</Link> of the page that is being rendered.


## Non-HTML content

Instead of returning `documentHtml`, the `onRenderHtml()` hook can set <Link href="/pageContext#content">`pageContext.content`</Link> to render a page that isn't HTML, such as an RSS/Atom feed, a sitemap, a Markdown file, or an image.

```ts
// pages/feed/+route.ts

export default '/feed.atom'
```

```ts
// pages/feed/+onRenderHtml.ts
// Environment: server

export { onRenderHtml }

import type { PageContextServer } from 'vike/types'

function onRenderHtml(pageContext: PageContextServer) {
  pageContext.content = `<?xml version="1.0" encoding="utf-8"?>
<feed xmlns="http://www.w3.org/2005/Atom">
  <title>My blog</title>
</feed>`
}
```

The value of `pageContext.content` can be:
 - A `string`
 - A `Uint8Array` (binary content, such as images)
 - A `ReadableStream<Uint8Array>` (streamed to the client upon SSR)

The HTTP response body is `pageContext.content` as-is: Vike doesn't inject any `<script>` or `<style>` tags.

If `onRenderHtml()` returns `documentHtml` then `pageContext.content` is ignored: you can use your own `pageContext.content` property in HTML pages, and if you define its type (see <Link href="/pageContext#typescript" />) then Vike's type is replaced by yours.

Upon <Link href="/pre-rendering">pre-rendering</Link>, the content is written to the file at the page's URL: `/feed.atom` => `dist/client/feed.atom`.

> With <Link href="/client-routing">Client Routing</Link>, add `rel="external"` to links pointing to non-HTML pages (e.g. `<a href="/feed.atom" rel="external">`), so that the browser fetches them instead of Vike's client-side router. See <Link href="/clientRouting#links-intercepting" />.

> If your server uses `pageContext.httpResponse.body` (see <Link href="/renderPage" />), use `pageContext.httpResponse.pipe()` or `pageContext.httpResponse.getReadableWebStream()` for binary and streamed content instead: `httpResponse.body` works only with a string and <Link href="/streaming#pagecontext-httpresponse-getbody">`httpResponse.getBody()`</Link> decodes the content as UTF-8 text.
