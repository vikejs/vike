`throw abort()` aborts a client-side navigation: the user stays on the current page.

For example, to ask for confirmation before leaving a page with unsaved changes:

```ts
// /pages/+onBeforeRoute.client.ts
// Environment: client

import type { PageContextClient } from 'vike/types'
import { abort } from 'vike/abort'

export function onBeforeRoute(pageContext: PageContextClient) {
  // onBeforeRoute() is also called when Vike prefetches a link
  if (pageContext.isPrefetch) return
  if (hasUnsavedChanges() && !window.confirm('Leave this page? Your changes will be lost.')) {
    throw abort()
  }
}
```

> The browser's [`beforeunload` dialog](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event) isn't shown upon client-side navigation.

You can use `throw abort()` only in <Link href="/onBeforeRoute">`onBeforeRoute()`</Link>, upon client-side navigation. The check must be synchronous (e.g. `window.confirm()`), as <Link href="/route-function#async">asynchronous routing is deprecated</Link>.

Upon back/forward navigation, Vike reverts the URL. (In browsers that don't support the [Navigation API](https://developer.mozilla.org/en-US/docs/Web/API/Navigation_API), if the user jumps over several history entries at once, then Vike only reverts one entry.)
