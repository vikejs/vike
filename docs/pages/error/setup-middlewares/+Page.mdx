This error means that your app has a <Link href="/middleware">`+middleware`</Link> but your server renders pages by calling <Link href="/renderPage">`renderPage()`</Link> itself. Vike can't tell whether your `+middleware` ran (e.g. an authentication `+middleware`), so it answers with a `500` instead of rendering the page.

Use one of the following instead of `renderPage()`:
- <Link href="/vike(app)">`vike(app)`</Link> (`@vikejs/*` 0.4 or later), which runs all `+middleware` around your routes.
- Vike's built-in server: <Link href="/server#server-true">`+server: true`</Link>.
- Apply <Link href="/middleware#manual-integration">`globalContext.middlewares`</Link> yourself: the list ends with Vike's pages.

If your server applies `globalContext.middlewares` and also has its own catch-all route calling `renderPage()`, delete that route: the list already renders your pages.


## `+middleware` rendering a page

A `+middleware` can't render a page with `renderPage()` either. Return what the page needs as context instead: Vike's pages render after every `+middleware`, with the context added to `pageContext`. To change Vike's response, return a response function.


## What Vike can't detect

Vike doesn't detect:
- A server that applies only some of your `+middleware` (e.g. only the handlers).
- A route of your server that answers before your `+middleware` run, without rendering a page (e.g. an `/auth/*` route defined before applying `globalContext.middlewares`).

We recommend testing your setup: for example, send a request without credentials to a URL that your authentication `+middleware` protects, and check that it's rejected.
