`vike/runtime` tells code in which environment it runs, and loads the page's <Link href="/config">config values</Link> of that environment.

```ts
import { environmentName, viteEnvironmentName, loadPageConfig } from 'vike/runtime'

console.log(environmentName) // 'server', 'client', or a named environment such as 'rsc'
console.log(viteEnvironmentName) // 'ssr', 'client', 'rsc', ...

const { config } = await loadPageConfig(pageContext.pageId)
```

- `environmentName: string` is the name of the Vike environment:
  - `'rsc'` (or any other name) if the Vite environment is a <Link href="/meta#named-environments">named environment</Link>.
  - Otherwise `'server'` or `'client'`, depending on whether the Vite environment is server-side or client-side (e.g. Vite's `ssr` environment, or a Cloudflare Worker environment, is `'server'`).
- `viteEnvironmentName: string` is the name of the [Vite environment](https://vite.dev/guide/api-environment).
- `loadPageConfig(pageId: string): Promise<{ config }>` loads the config values of the page `pageId` that live in the environment `environmentName`.
  - A named environment only gets the config values that name it (e.g. `+meta` with `env: { rsc: true }`, or `+Page.rsc.js`): it doesn't get the `server` config values.
  - If there aren't any config values in the environment, then `config` is `{}`.
  - It throws an error if `pageId` doesn't exist.

| Vite environment | `environmentName` | `viteEnvironmentName` | `loadPageConfig()` returns |
| --- | --- | --- | --- |
| `ssr` | `'server'` | `'ssr'` | The `server` config values |
| `client` | `'client'` | `'client'` | The `client` config values |
| `rsc` (named by `meta.env`) | `'rsc'` | `'rsc'` | The `rsc` config values |
| Server-side and not named by `meta.env` (e.g. a Cloudflare Worker) | `'server'` | Its name | The `server` config values |
| Client-side and not named by `meta.env` | `'client'` | Its name | The `client` config values |


## Example

A React Server Components integration renders `+Page` and `+Layout` in an `rsc` environment:

```js
// /pages/+config.js
// Environment: config

export default {
  meta: {
    Page: {
      env: { server: false, client: false, rsc: true }
    },
    Layout: {
      env: { server: false, client: false, rsc: true },
      cumulative: true
    }
  }
}
```

```jsx
// /renderer/getPageElement.jsx
// Environment: rsc

import { environmentName, loadPageConfig } from 'vike/runtime'

if (environmentName !== 'rsc') throw new Error('getPageElement() should only run in the rsc environment')

export async function getPageElement(pageContext) {
  const { config } = await loadPageConfig(pageContext.pageId)
  const { Page, Layout = [] } = config
  let page = <Page />
  Layout.forEach((Layout) => {
    page = <Layout>{page}</Layout>
  })
  return page
}
```

The `rsc` environment must exist in Vite's `config.environments` (it's usually created by the integration, e.g. [`@vitejs/plugin-rsc`](https://github.com/vitejs/vite-plugin-react/tree/main/packages/plugin-rsc)). Vike doesn't add build inputs to named environments: their pages are loaded lazily by `loadPageConfig()`.


## Why the environment isn't an argument

`loadPageConfig()` always loads the config values of the environment it runs in: you can't load the config values of another environment. That's because each Vite environment has its own module graph: the modules of `+Page.rsc.js` are loaded (and bundled) by the `rsc` environment and can't be loaded by the `ssr` environment.

To use another environment, run code in that environment and communicate with it (e.g. `@vitejs/plugin-rsc`'s `import.meta.viteRsc.loadModule()`).

> `vike/runtime` can only be imported by modules that Vite transforms for the environment they run in. A package in `node_modules` that imports it must be listed in `resolve.noExternal` of every server environment that loads it (unless that environment bundles all dependencies). It can't be imported from `+config` files or from Node.js code that Vite doesn't process.
