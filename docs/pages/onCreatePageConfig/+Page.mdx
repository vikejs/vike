Vike extensions can use `+onCreatePageConfig_experimental()` to set a page's config depending on the page's code.

<Warning>`+onCreatePageConfig_experimental()` is experimental: expect breaking changes in any minor version update.</Warning>

```ts
// node_modules/vike-some-extension/config.ts
// Environment: config

import type { Config, OnCreatePageConfig } from 'vike/types'

const onCreatePageConfig: OnCreatePageConfig = async (page, { read }) => {
  const [{ filePathAbsolute }] = page.imports('Page')
  const code = await read(filePathAbsolute!)

  // A .ssr.js hook doesn't run upon client-side navigation, while a .server.js hook does
  const fileName = code.includes('useServerData') ? 'hook.server' : 'hook.ssr'
  return {
    onCreatePageContext: `import:vike-some-extension/__internal/${fileName}:onCreatePageContext`,
  }
}

export default {
  name: 'vike-some-extension',
  onCreatePageConfig_experimental: onCreatePageConfig,
} satisfies Config
```

Vike calls it for each page at build time (and in development), and adds the returned configs to the page as if they were set by the `+config` file that defines the hook. The user's `+` files keep precedence, see <Link href="/config#inheritance" />.

> See also: <Link href="/file-env" />


## Arguments

- `page.pageId`
- `page.isErrorPage`
- `page.config`: the page's config, without the configs returned by `onCreatePageConfig_experimental()`.
- `page.hasServerOnlyHook`: whether the page has a server-only hook, in which case Vike fetches `pageContext` from the server upon client-side navigation.
- `page.imports(configName)`: the files the page imports for a config, in every environment, e.g. `page.imports('Page')` returns both `+Page.client.js` and `+Page.server.js` if the page defines both.
- `resolve(importPath, importer?)`: resolves an import path with Vite's resolver.
- `read(filePath)`: reads a file. In development, when the file is modified, Vike calls the hook again and reloads the page if the returned configs changed.


## Limitations

- It can only return configs loaded at runtime: it can't return config-time settings such as `prerender` or `clientRouting`.
- The returned configs must not depend on the Vite environment calling the hook.
