Define `+middleware` to add server middlewares, for all URLs or only for the URLs matching a `path`. Write them with [Universal Middleware](https://github.com/magne4000/universal-middleware) to use them with any server (Hono, Express, ...).

```ts
// pages/+middleware.ts

import { enhance, MiddlewareOrder } from '@universal-middleware/core'

// This middleware protects all URLs /admin/**
export default enhance(
  async (request: Request) => {
    if (!request.headers.has('authorization')) {
      return new Response('Unauthorized', { status: 401 })
    }
  },
  { name: 'adminAuth', path: '/admin/**', order: MiddlewareOrder.AUTHORIZATION }
)
```

> You can also export an array of middlewares.


## With `vike(app)`

<Link href="/renderPage#renderpage-vs-vike-app">`vike(app)`</Link> runs your `+middleware`.


## Without `vike(app)`

<Link href="/renderPage">`renderPage()`</Link> doesn't run your `+middleware`. Apply `globalContext.middlewares` instead. Its last element renders your pages, so it replaces your own `renderPage()` route.

<Tabs choice={'server'} />

:::Choice{#Fastify}
Apply the list in one call: a second call throws. Your handlers then run before your routes.
:::

:::Choice{#Elysia}
Apply the list in one call: with two calls, the pages are never reached. Your handlers then run before your routes.
:::

:::Choice{#Other}
Use the `apply()` of [your server's Universal Middleware adapter](https://universal-middleware.dev/reference/supported-adapters). The example uses srvx, whose `apply()` returns a fetch handler.
:::

```ts choice=Hono
// server/index.ts
// Environment: server

import { Hono } from 'hono'
import { apply } from '@universal-middleware/hono'
import assert from 'node:assert'
import { getGlobalContext } from 'vike/server'

const app = new Hono()

const globalContext = await getGlobalContext()
// Narrows globalContext down to the server-side one
assert(!globalContext.isClientSide)
const { middlewares } = globalContext

// Before your routes: the +middleware that aren't handlers
apply(app, middlewares.filter((m) => !m.isHandler))

app.get('/api/hello', (c) => c.text('Hello'))

// After your routes: the handlers and the pages
apply(app, middlewares.filter((m) => m.isHandler))
```

import { Elysia } from 'elysia'

```ts choice=Other
// server/index.ts
// Environment: server

import { serve } from 'srvx'
import { apply } from '@universal-middleware/srvx'
import assert from 'node:assert'
import { getGlobalContext } from 'vike/server'

const globalContext = await getGlobalContext()
// Narrows globalContext down to the server-side one
assert(!globalContext.isClientSide)
const { middlewares } = globalContext

serve({ fetch: apply(middlewares) })
```


## `path` and `order`

A `+middleware` with a `path` and no `order`, or with `order: 0`, is a handler.

- Handlers run after your routes, right before your pages: a route of your server can answer instead of a handler (except with `apply()` on Fastify and Elysia, as above).
- For a URL, only the handler with the most specific `path` runs. If it returns nothing, the request goes on to your pages.
- The other `+middleware` run before your routes, sorted by `order`. To run a `+middleware` for the URLs matching its `path` (e.g. a guard on `/admin/**`), give it a negative `order` such as `MiddlewareOrder.AUTHORIZATION`.

A `path` is matched against the page's URL, without the Base URL. It also covers the page's `.pageContext.json` request.


## Development

When a `+middleware` changes, `$ vike dev` re-runs the `+server.js` (or restarts the `+serverEntry.js`) that applies `globalContext.middlewares`. A server you run yourself needs a restart.
