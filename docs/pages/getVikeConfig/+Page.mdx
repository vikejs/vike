Get the app's <Link href="/config">configurations</Link> that are available at config-time.

<Warning>It's a beta feature: expect breaking changes in any minor version update.</Warning>

> It only returns configurations that are available at config-time (i.e. at build- and dev-time). To get configurations at (production) runtime use <Link href="/globalContext#config">`globalContext.config`</Link> and <Link href="/globalContext#pages">`globalContext.pages`</Link> instead.

```ts
// vite.config.ts

import type { UserConfig, Plugin } from 'vite'
import { getVikeConfig } from 'vike/plugin'

export default {
  plugins: [myVitePlugin()]
} satisfies UserConfig

function myVitePlugin(): Plugin {
  return {
    name: 'myVitePlugin',
    configResolved(config) {
      const vike = getVikeConfig(config)
      console.log(vike.config.prerender)
      console.log(vike.config.baseAssets)
      console.log(vike.config.baseServer)

      console.log(vike.pages['/pages/index'].config)
      console.log(vike.pages['/pages/product'].route)

      // If you pre-render pages
      console.log(vike.prerenderContext.pageContexts)
      console.log(vike.prerenderContext.output)
    },
    config(config) {
      // Also available here
      const vike = getVikeConfig(config)
    }
  }
}
```

## Set a page config

A Vite plugin can set a configuration of a page that is loaded at runtime (e.g. a hook), as if a `+` file of the page set it:

```js
// my-vite-plugin.js

export default {
  name: 'my-vite-plugin',
  vike: {
    // Vike calls it for each of its configs (e.g. after a `+` file is created), before it generates its virtual files
    onPageConfigs({ pages }) {
      pages['/pages/product'].config.onCreatePageContext =
        'import:my-vite-plugin/onCreatePageContext.server:onCreatePageContext'
    }
  }
}
```

The page's `+` files have precedence. Setting a page config afterwards (e.g. upon a file change) reloads the page in development and throws an error when building.

> `onPageConfigs()` also receives `environment`, the Vite environment loading Vike's virtual file (or the one given to `rerunOnPageConfigs()`), and `resolve(source, importer)`, which resolves an import as that environment's Vite plugins do. Vike awaits it.

If your Vite plugin reads files to set page configs, call `rerunOnPageConfigs()` when one of them is modified. Vike then calls `onPageConfigs()` again and generates its virtual files only after it:

```js
// my-vite-plugin.js

import { readFileSync } from 'node:fs'
import { rerunOnPageConfigs } from 'vike/plugin'

export default {
  name: 'my-vite-plugin',
  vike: {
    onPageConfigs({ pages }) {
      // ./product.json is e.g. { "onCreatePageContext": "import:my-vite-plugin/onCreatePageContext.server:onCreatePageContext" }
      const { onCreatePageContext } = JSON.parse(readFileSync(new URL('./product.json', import.meta.url), 'utf8'))
      pages['/pages/product'].config.onCreatePageContext = onCreatePageContext
    }
  },
  async hotUpdate({ file }) {
    // Vite calls hotUpdate() for each of its environments
    if (this.environment.name === 'client' && file.endsWith('/product.json')) {
      await rerunOnPageConfigs(this.environment)
    }
  }
}
```

<Warning>
  Setting a page config is experimental.
</Warning>
