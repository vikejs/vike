The `vike(app)` function installs Vike's server middlewares to your server.

> See <Link href="/server" /> for how to use `vike(app)`.

It installs:
- Vike's handler that renders your pages (basically <Link href="/renderPage">`renderPage()`</Link>)
- Every <Link href="/middleware">`+middleware`</Link> from <Link href="/extensions">Vike extensions</Link>

> Technically, what it does is install the <Link href="/globalContext#middlewares">`globalContext.middlewares`</Link> list using the [sandwich approach](https://github.com/vikejs/vike-server-adapters#sandwich-approach): middlewares (i.e. non-handlers) are applied before user-defined routes while handlers are applied after — so that your routes can read the context set by the middlewares of Vike extensions.
>
> See also: <Link href="/middleware#order" />

> It uses [Universal Middleware](https://universal-middleware.dev) under the hood.


## API

```ts
// Environment: server

import vike from '@vikejs/hono' // Or @vikejs/express, @vikejs/fastify, @vikejs/h3, @vikejs/elysia

vike(
  // [Required] Your server app, e.g. new Hono()
  app,
  // [Optional] List of Universal Middlewares, e.g. [compress()]
  middlewares
)
```

### `app`

Your server app: `new Hono()`, `express()`, `fastify()`, `new H3()`, or `new Elysia()`.

Call `vike(app)` once, before defining your routes — so that the <Link href="/middleware">`+middleware`</Link> of Vike extensions (e.g. authentication) run before your routes.

> `vike(app)` throws an error if you call it twice on the same app, or (with Hono, Express, and Elysia) if a route is already defined.

### `middlewares`

List of [Universal Middlewares](https://universal-middleware.dev) to install together with `+middleware` — for example [`compress()`](https://universal-middleware.dev/middlewares/compress), see <Link href="/server#compression" />.

They're installed the same way as `+middleware`:
- Middlewares (i.e. non-handlers) run before your routes, while handlers run after your routes — see <Link href="/middleware#order" />.
- Middlewares are sorted by `order` together with `+middleware` — with the same `order`, they run after `+middleware` (and can therefore read the context set by `+middleware`).

Unlike `+middleware`, middlewares (i.e. non-handlers) passed to `vike(app, middlewares)` also run if a previous middleware already answered with a `Response` — for example, `compress()` also compresses a `Response` returned by a `+middleware`.


## Manual integration

If your favorite server framework doesn't have a `vike(app)` adapter yet, you can manually apply <Link href="/globalContext#middlewares">`globalContext.middlewares`</Link> around your routes like this:

```ts
// +server.ts
// Environment: server

import { YourFavoriteServer } from 'your-favorite-server'
import { apply } from '@universal-middleware/your-favorite-server'
import { getGlobalContext } from 'vike'
import assert from 'node:assert'

const globalContext = await getGlobalContext()
assert(!globalContext.isClientSide)
const { middlewares } = globalContext
const app = new YourFavoriteServer()

// Apply globalContext.middlewares around your routes (the sandwich approach):

// The +middleware that aren't handlers first
apply(app, middlewares.filter((m) => !m.isHandler))

// Your routes
app.get('/api/me', getMe)

// The +middleware that are handlers last (it includes Vike's handler that renders your pages)
apply(app, middlewares.filter((m) => m.isHandler))

export default {
  fetch: app.fetch,
}
```

> If [Universal Middleware adapter](https://universal-middleware.dev/) doesn't have a `@universal-middleware/your-favorite-server` adapter yet, you can consider asking your agent to create one (agents are proficient at this).

> In development, because `globalContext.middlewares` is read when your server starts, you must restart your server after a `+middleware` changes (i.e. you install/remove/update a Vike extension).
>
> Note that `vike(app)` doesn't need a restart because, in development, it re-reads `globalContext.middlewares` for every request.

> In principle, it's possible to use <Link href="/renderPage">`renderPage()`</Link> together with manually installing `globalContext.middlewares`, similar to the approach shown above. But it's cumbersome, and we don't recommend it. (You'd need to remove Vike's handler from `globalContext.middlewares`, while both `renderPage()` and `globalContext.middlewares` require a catch-all route which leads to conflicts.)
